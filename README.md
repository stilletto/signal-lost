# Signal Lost

A mobile-first FPV combat-drone simulator. [Android v253 with FPS](https://stilletto.github.io/signal-lost/signal-lost.apk), [HEAVY v253 with FPS](https://stilletto.github.io/signal-lost/signal-lost-heavy-fps.apk), or [play the retained Web v246](https://stilletto.github.io/signal-lost/).

Android v253 brings the live tracer ribbon into the existing Loading preflight and uses Godot's native compact town shadow mesh. Across eighteen heavy-map blocks, shadow positions fall 116,719 -> 41,399 while all colour arrays, windows, interiors, base triangles and LOD corners remain identical. No tactical density, texture quality or model detail is removed. This reduces shadow input work; it does not establish a handset FPS improvement. Existing RenderBudget also gains opt-in raw frame boundaries; ordinary player runs have no new profiling hooks/history.

The regular ARM64 APK opens the menu. HEAVY opens The Third Knock with three aircraft and reserves following at 15 / 60 metres. Both show FPS, retain the package/signing identity, all 26 launcher entries and careers. No fresh profile, pilot, timed exit, free purchase, profiler or frame cap is baked in. Normal is 94,495,708 bytes, 4 KiB above v252; HEAVY is 94,495,708 bytes, unchanged. Both are about 90.1 MiB.

The packages use source c92b2eb18b620906036211a98382fa0d1717acfd. The exact 742 frozen source/test/tool/project/locale inputs and 1,522 assets reuse the completed 1,945-test / 77,907-assertion, 62-scenario gates. No fresh full-suite run is claimed for packaging; 22 offline release-tool cases pass. All 141 compiled scripts agree between players. Of 2,741 game entries, only startup arguments differ between normal and HEAVY. Three compiled scripts change from v252; all 233 textures, 9 audio samples, UID/class caches and both engine libraries remain exact. Fifty reserialized scenes agree in all properties after normalizing 114 generated editor IDs and resource-reference labels.

Nine desktop Compatibility jobs run extracted APK resources, with eight new frames viewed and fourteen source Mobile frames reused (two are explicitly invalid shadow controls). Two separate headless compiled-resource reads reproduce the source's colour/LOD and shadow hashes exactly. A screenshot-free 50-second heavy pair records real fire and both reserve takeovers; p95 wall intervals are 33.88 / 34.14 ms and maxima 48.77 / 51.92 ms for v252 / v253 under a 30 FPS desktop cap. GPU timings are not a causal comparison: the baseline private parser initially rejected the old profile schema, so its completed log/profile was recovered without repeating the flight, but its raw GPU activity series was lost. Candidate frame-phase and activity records are retained. GL first-fire pipeline counters are zero in both versions; the source Mobile preflight result remains separate.

Heavy geometry still exceeds budget (candidate p95 301 submissions / 274,160 triangles); the direct automated approach loses all three aircraft without entering the shelter at 44.3 seconds. Handset >=30 FPS and a reliable winning route remain unaccepted. Screenshot-bearing flights are excluded from timing claims. Earlier Count/convoy observations and GL exit diagnostics in build.json are explicitly historical, not rerun here.

The browser remains Web v246, source dbd60a5367e50e481fec7289f2aa3e0844763b3c; its PCK, WASM, icon and privacy page stay exact. No new Web export, browser-career acceptance, phone install/launch, Play release or paid-provider call occurs. A new agreed free Samsung window is required for physical timing. Shared ADB and editor settings are preserved; player careers remain intact.
